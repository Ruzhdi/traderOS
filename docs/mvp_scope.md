#### Must-have features

Features that are required for the MVP to be considered functional.

This section should include only the core functionality that must work in the first usable version of TraderOS, such as:

* user registration and login;
* JWT-protected endpoints;
* trade creation, listing, updating and deletion;
* PostgreSQL storage;
* basic trade filters;
* basic trading statistics;
* screenshot upload;
* Docker-based local setup;
* Swagger/OpenAPI documentation;
* basic tests.

#### Should-have features

Features or engineering improvements that are important, but not strictly required for the first working MVP.

This section may include:

* GitHub Actions CI;
* deployment;
* seed/demo data;
* improved README examples;
* basic architecture documentation;
* database schema documentation.

#### Could-have features

Optional features that may be added only after the must-have and should-have parts are stable.

This section may include:

* AI journal summary;
* CSV export;
* simple frontend page;
* more advanced analytics;
* improved reporting.

#### Won’t-have in MVP

Features that are intentionally excluded from the MVP to prevent scope creep.

This section should explicitly exclude:

* React/Next.js dashboard;
* broker integrations;
* TradingView integration;
* backtesting engine;
* payments;
* multi-user teams/workspaces;
* mobile app;
* advanced AI trading coach;
* Kubernetes or advanced infrastructure.

#### MVP Definition of Done

A clear checklist that defines when the MVP can be considered complete.

This section should answer:

* What must work end-to-end?
* What must be tested?
* What must be documented?
* What must be runnable by another developer?
* What proves that the project is ready to be shown as a backend portfolio project?
